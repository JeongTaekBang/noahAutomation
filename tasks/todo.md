# AX Sales order book 비상 생성 — 타당성 검토 (2026-10-29)

사용자 요청: AX Sales order book이 갱신 안 되는 달에 Item requirement(IR) export로 오더북(Raw 시트 형식)을
뽑아 마감할 수 있게. 2026년분만. 자료: `ax_orderbook/Sales order book_09_2026.xlsx`(Raw 시트만 본다),
`ax_orderbook/Item requirement_20261028.xlsx`(Created date ≥ 2025-01-01, All).

실측으로 확정한 것:
- Raw 그레인 = Key(Project + Cost center + Prod/Dept(Revenue)) × Period. `Start + Input − Output + Variance = End`가
  7,982행 전부 성립, `Start(P) = End(P−1)`(예외 3행은 회계 수기)
- Raw의 회계 추가 열(G Key, H Adjusted code, I Category, J Restate, L/AN 이름, AA/AB Total input, AO/AP, AS~AV)은
  **전부 수식** → 만들 것은 AX 원본 열뿐. 숫자 열 수식은 8칸(회계 수기 보정), AG(Order Book Code) 118칸은 외부 파일 VLOOKUP
- 하류(Backlog/Orders 시트) Orders = Total Value input = Input + Variance = **End − Start + Output** →
  정확해야 하는 건 Output과 End 둘
- IR `Net amount`는 **거래통화**(통화 열 없음). 외화 고객 21곳(USD/EUR/GBP/JPY)을 환산비로 역추적.
  Output = Net × **출고월** 월환율 (NOAH FX 시트와 1e-6 일치 267/295, 나머지는 JPY), Input = **수주월** 환율
  (302/333 1원 이내). 외화 잔고는 매월 재평가 안 함 → 환차는 출고월 Variance로
- Input = 라인 `Created date`의 월 — **UTC라 +9h**(프로젝트 생성일과 KST 98.9% / UTC 90.6% 일치)
- Output = `Line status = Invoiced` + `Actual ship date` 월 — 같은 달 98.5%(2,219/2,252키),
  월말 출고→익월 청구 27키. `Actual ship date`는 출고일이고 부분출고 라인은 **마지막 출고일만** 남는다
  (82-17383.002: 8월 30 + 9월 78 → IR엔 9/28 하나). Open 라인은 `Deliver remainder`가 잔량
- 취소 라인은 `Net amount = 0`, 취소일 없음 (82-17932.001 330M이 10월 취소 → 과거 잔고 재현 불가)
- Prod/Dept(Material) → (Revenue)는 산술식 하나가 아니다(1034→0134, 1172→0272, 1600→0700, 3000→0108) —
  46쌍 학습, 미매핑 11코드 49라인
- Cost center ≠ IR Division 105 프로젝트(4%) — TS NEXGEN·VTL 등 FP Spares/NOD/NOS(CC 30, 품목 0011070은

# DN_국내 출고기록 자동화 — `create_dn.py` (2026-08-07) — 완료

## 알려진 한계

- 반품(계산서금액 음수)이 낀 건은 확인 필요로 뺀다 — 출고/반품/재출고를 어떻게 적을지는
  사람이 정한다 (6개월 1건: `SOD-2026-0280`)
- 세금계산서 발행일은 **채우지 않는다** (사용자가 직접 입력). 월합 거래처 12곳
  (사업자번호 기준)에는 Remarks를 물려주는데, 그 표기가 기존 DN에 29~100%로 들쭉날쭉해
  과거 입력분과는 어긋날 수 있다 — 정보용이라 틀려도 매출에는 영향이 없다
- DN_ID는 출고리스트 1행당 1개. 사람이 같은 거래처 여러 건을 한 DN으로 묶은 경우와는
  번호가 갈린다 (P08 `DND-2026-0749` 오토밸브 2건)
- 출고리스트 날짜와 사람이 적은 날짜가 다르면 우리는 출고리스트를 따른다.
  라인·수량이 정확히 같으면 건너뛰지만, 다르게 쪼개 적은 건(`SOD-2026-0301` 6/30 → 7/1·7/20)은
  중복으로 생성될 수 있다 — 지난 기간을 뒤늦게 돌릴 때만 생기는 문제라 미리보기로 확인할 것
- 쓴 뒤 파워쿼리 새로고침은 사람 몫 (`SO_통합`·`Order_book` 반영)
