# NOAH Dashboard 사용 가이드

---

## 1. 소개

NOAH 인터컴퍼니 거래 현황을 한눈에 파악할 수 있는 대시보드입니다.
Excel로 관리 중인 수주(SO)/발주(PO)/출고(DN) 데이터를 자동으로 시각화합니다.

### 주요 기능 (10페이지)

| 페이지 | 설명 |
|--------|------|
| 오늘의 현황 | KPI 카드, 납기 캘린더, PO 확정 지연, EXW 완료 미출고, 납기 현황, 해외 선적 Action Items, 세금계산서 미발행 |
| 수주/출고 현황 | 월별 수주/출고 추이, Book-to-Bill, 일별 수주/출고 히트맵 |
| 제품 분석 | 매출 Top 15(클릭 드릴다운), 구성비, 월별 추이, 평균단가, Backlog, Deep Analysis(ABC/성장률/매트릭스) |
| 섹터 분석 | 섹터별 매출(클릭 드릴다운), 월별 추이, 제품 믹스, Backlog, 평균 주문 규모 |
| 고객 분석 | 고객별 매출 Top 15(클릭 드릴다운), Pareto, 월별 추이, Deep Analysis(ABC/성장률/수익성) |
| 발주 커버리지 | 미발주/부분발주/발주진행중/발주확정 KPI, 상세 테이블, 고객별/섹터별 분석 |
| 수익성 분석 | 매출 vs 원가(ICO) 월별 마진 추이, 3탭(고객별/섹터별/모델별), 저마진 경보 Top 10 |
| Order Book | Executive(워터폴/KPI), Risk(Aging/위험건), Conversion(리드타임/Box plot) |
| 정합성 | 검사(0이어야 하는 것 전부 — `check_data.py`와 같은 결과), 마감 후 변동(마지막 마감 뒤 달라진 수주·매출·잔고) |
| 동기화 로그 | Excel → DB 동기화 때 기록된 신규/수정/삭제 이력 탐색, 주문 타임라인 |

## 2. 사용 방법

**별도 프로그램 설치가 필요 없습니다.**

### 설치 (처음 한 번)

1. 공유받은 **NOAH_대시보드_배포.zip** 의 압축을 풉니다.
2. **설치.bat** 을 더블클릭합니다 (1~2분).
3. 바탕화면에 **[NOAH 대시보드]** 아이콘이 생깁니다.

### 실행

바탕화면 아이콘을 더블클릭하면 기본 브라우저에 대시보드가 열립니다.
브라우저 탭을 닫아도 서버는 남습니다 — 완전히 끝내려면 로그아웃하거나 PC를 재시작하세요.

### DB 파일

- `noah_data.db`는 OneDrive를 통해 공유됩니다. 담당자가 공유한 **NOAH ACTUATION** 폴더를
  [내 파일에 바로가기 추가]로 받아 동기화가 끝나면 준비 완료입니다.
- 못 찾는다는 안내가 뜨면 설치 폴더의 **설정.bat** 을 실행해 `noah_data.db`가 들어 있는
  **폴더** 경로를 적습니다 (파일 경로가 아니라 폴더 경로입니다).

```ini
[paths]
data_folder = C:\Users\홍길동\OneDrive - Rotork plc\...\NOAH ACTUATION
```

> 대시보드는 원본을 직접 열지 않고 **사본을 떠서** 읽습니다. 그래야 OneDrive가 파일을
> 갱신하는 것을 막지 않고("충돌된 사본" 방지), 한 시점의 일관된 데이터가 보장됩니다.

### 업데이트 / 제거

- **업데이트**: 새 zip을 받아 `설치.bat` 을 다시 실행합니다. 지정해 둔 DB 경로는 유지됩니다.
- **제거**: 설치 폴더(`%LOCALAPPDATA%\NOAH_Dashboard`)의 `제거.bat` 을 실행합니다.
- **버전 확인**: 설치 폴더의 `BUILD_INFO.txt` 첫 줄. 문의 시 이 값을 알려주세요.

### 사이드바 필터

모든 페이지에 공통 필터가 적용됩니다:

- **시장 구분**: 전체 / 국내 / 해외
- **연도**: 전체 또는 특정 연도 선택
- **월**: 전체 또는 특정 월 선택 (연도 = 전체 시 비활성)
- **섹터**: 복수 선택 가능
- **고객**: 접이식(Expander) 내 복수 선택 가능
- **데이터 새로고침**: 캐시 초기화 (5분마다 자동 갱신)
- **데이터 기준**: DB 마지막 sync 시각. 하루가 넘으면 경고, 일주일이 넘으면 오류로 표시됩니다
  — 각자 PC의 OneDrive 사본을 읽으므로 동기화가 늦으면 사람마다 다른 숫자를 볼 수 있습니다
- **데이터 로드 오류 배너**: DB 쿼리 실패 시 페이지 상단에 경고 표시 (어떤 로더가 실패했는지, 에러 유형 포함). "데이터 없음"과 "쿼리 실패"를 구분 가능

## 3. 페이지별 안내

### 오늘의 현황

당일 기준 주요 Action Items:

- **KPI 카드 (4개)**: 오늘 납기 / 이번 주 납기 / 금월 수주 / 금월 출고
- **납기 캘린더**: 월별 히트맵, 날짜 클릭 시 상세 드릴다운
  - EXW 출고 예정 / 공장 픽업 / 납기 예정 / 출고 실적
- **PO 확정 지연**: Sent → Confirmed 대기 건, Aging 버킷별(7일/8~14일/15~30일/30일+) 분류
  - 국내 / 해외 탭 분리
- **EXW 완료 미출고**: PO EXW 일자 경과 but 미출고(Invoiced 아님) 건
  - 라인 아이템 단위, Aging 버킷별 분류, 국내 / 해외 탭 분리
- **납기 현황**: 납기일 경과 but DN 미완료/부분 출고 건
  - 잔여 수량/금액 표시, 국내 / 해외 탭 분리
- **해외 선적 Action Items** (시장 ≠ 국내 시 표시):
  - 선적 대기 / 포워더 미정 건
  - 공장 출고일, 픽업일, 선적 예정일, B/L, 포워더 정보
- **세금계산서 미발행** (국내 전용):
  - KPI 4개(건수/금액/최대 경과일/30일 초과 건수)
  - Aging 바 차트 + 고객별 금액 Top 10
- **SO/DN 불일치**: 과다출고·단가 불일치 (정합성 검사와 같은 함수 — DN 라인별 내역은 여기서 본다)
- **Customer PO 미변경 단가/수량 변동** — 고객 PO는 그대로인데 SO의 수량·단가가 바뀐 것. 확인할 때까지 남는다:
  - **주문 단위 카드**: 한 주문이 한 동기화에서 바뀐 라인들이 카드 하나다. 라인별 변경과 금액 영향이 표로 나온다
  - **단계** — 그 변경을 한 시점에 물건이 어디까지 가 있었나. 무거운 것부터 나온다:

    | 표시 | 뜻 |
    |------|----|
    | 🔒 마감 뒤 변경 · 마감된 달 매출 | 그 달 마감 스냅샷이 굳은 뒤에 고쳤다 — 다음 마감의 Variance가 된다 ('정합성 → 마감 후 변동'에도 나온다) |
    | 🧾 출고 뒤 변경 · 매출 인식 | 출고한 뒤에 고쳤고 매출도 잡혀 있다 — 이미 나간 세금계산서·인보이스와 금액이 다를 수 있다 |
    | 🚚 출고 뒤 변경 · 매출 미인식 | 출고한 뒤에 고쳤고 아직 계산서 전이다 — 거래명세표와 금액이 다를 수 있다 |
    | 📦 미출고 / 변경 뒤 출고 | 고친 뒤 그 값으로 출고했거나 아직 안 나갔다 — 평소 업무 |

    DN 단가는 SO를 따라가므로(XLOOKUP) 출고 뒤에 SO를 고치면 이미 나간 문서의 금액과 갈린다. 그래서 단계는 **지금 상태가
    아니라 변경 시점 기준**이다
  - **금액 영향** = 바뀐 뒤 수량×단가 − 바뀌기 전 수량×단가. 같은 라인이 여러 번 바뀌었으면 각 변경을 그때 값으로 잰다.
    SO 라인이 그 뒤 지워졌으면 '확인 불가'
  - **사유**(선택)를 적고 **확인 완료**를 누르면 그 카드의 라인 전부가 한 번에 확인된다 (전부 아니면 전무)
  - **확인 이력**: 카드 목록 아래 — 확인 시각·확인자·사유·주문·변경 내용. 확인한 것은 카드에서 사라지므로 여기서만 다시 볼 수 있다

### 수주/출고 현황

- **KPI 카드 (6개)**: 금월 수주(전월 대비) / 전월 수주 / 누적 수주 / 금월 출고(전월 대비) / 전월 출고 / Book-to-Bill
- **월별 수주/출고 금액 추이**: 그룹 막대 + 누적매출 라인
- **Book-to-Bill 월별 추이**: 라인 차트 (1.0 기준선)
- **일별 수주/출고 현황**: 월 선택기 + SO/DN 듀얼 히트맵

### 제품 분석

- **KPI 카드 (3개)**: 총 제품 종류 / 최다 판매 제품 / 최고 매출 제품
- **제품별 매출 Top 15**: 가로 막대, 클릭 시 드릴다운 (월별 추이, 섹터 비중, 주요 고객 Top 5)
- **제품 구성비**: 도넛 차트 (Top 8 + 기타)
- **제품별 월별 추이 (Top 5)**: 누적 영역 차트
- **제품별 평균 단가 Top 15**: 가로 막대
- **제품별 Backlog Top 10**: 가로 막대
- **Deep Analysis**:
  - 제품 세그먼트 (ABC): 80/95 기준 3등급 분류
  - 제품 성장률: 전월 대비 성장 Top 5 / 하락 Top 5
  - 제품 × 고객 매트릭스: 히트맵 (Top 10 제품 × Top 10 고객)

### 섹터 분석

- **KPI 카드**: 섹터별 매출 비율 (최대 6개, 금액 + 비중%)
- **섹터별 매출 비율**: 파이 차트, 클릭 시 드릴다운 (제품 믹스, 월별 추이, 주요 고객 Top 5)
- **섹터별 월별 추이**: 누적 막대 차트
- **섹터별 제품 믹스**: 그룹 막대 (Top 8 제품)
- **섹터별 Backlog 현황**: 건수 + 금액 테이블
- **섹터별 평균 주문 규모**: 막대 차트

### 고객 분석

- **KPI 카드 (3개)**: 총 고객 수 / Top 고객 / 금월 수주 고객 수
- **고객별 매출 Top 15**: 가로 막대, 클릭 시 드릴다운 (월별 추이, 제품 믹스 도넛, Backlog 상세)
- **고객 집중도 (Pareto)**: 막대 + 누적 라인 (Top 20)
- **고객 상세 테이블**: 주문 건수, 수량, 금액, 최근 월, 평균 주문, Backlog
- **고객별 월별 매출 추이 (Top 5)**: 마커 라인 차트
- **Deep Analysis**:
  - 고객 세그먼트 (ABC): 3등급 분류
  - 고객 성장률: 전월 대비 성장 Top 5 / 하락 Top 5
  - 고객 수익성: 고객별 마진율 분석

### 발주 커버리지

PO Status 기반 발주 현황:

| 상태 | 의미 |
|------|------|
| 미발주 | PO 없음 또는 Open (공장 발주 전) |
| 부분 발주 | 일부 Open + 일부 Sent/Confirmed |
| 발주 진행중 | Sent (공장에 발주, 확인 대기) |
| 발주 확정 | Confirmed / Invoiced |

- **KPI 카드 (5개)**: 미발주 / 부분 발주 / 발주 진행중 / 발주 확정 / 발주 필요 금액
- **커버리지 요약**: 상태별 누적 가로 막대 (컬러 구분)
- **상태별 상세 테이블**: 미발주 / 부분 발주 / 발주 진행중 각각 SO별 상세
- **고객별 발주필요 금액 Top 10**: 가로 막대
- **섹터별 커버리지율**: 막대 차트 (100% 기준선)
- 출고 완료 건, PO 전체 Cancelled 건은 분석에서 자동 제외

### 수익성 분석

SO 매출 vs PO 원가(ICO) 마진:

- **KPI 카드 (4개)**: 총매출 / 총원가(ICO) / 총마진 / 마진율(%)
- **월별 마진 추이**: 그룹 막대(매출/원가) + 마진율 라인
- **3개 탭** (고객별 / 섹터별 / 모델별):
  - 각 탭: 마진율 Top 15 막대 차트 + 상세 테이블(매출, 원가, 마진, 미출고금액)
- **저마진 경보 Top 10**: 마진율 20% 미만 건
- 원가 미확정 건(PO 없음)은 마진 계산에서 제외되며 별도 안내

### Order Book (3탭)

- **Executive**:
  - 워터폴 차트 (월별 선택 / 누적 토글): Opening → Input → Output → Ending
  - KPI 3개: Backlog Cover(월), Past Due Ratio(%), Book-to-Bill
  - 월별 Order Book 테이블
- **Risk**:
  - 납기 지연 + 임박 건 그룹 분석 (고객, 시장, 섹터)
  - Aging 버킷 시각화
- **Conversion**:
  - Output → 매출 전환 리드타임 분석
  - 해외 물류 리드타임 (공장 → 픽업 → 선적): Box plot + 통계 요약 + 이상치 감지

### 정합성 (2탭)

사이드바의 시장·섹터·고객·기간 필터는 이 페이지에 적용하지 않는다 — 걸러서 나온 0건은 정상으로 읽히기 때문이다.

- **검사** — 정상이라면 한 건도 없어야 하는 것:
  - CLI `check_data.py`(메뉴 [V])와 **같은 함수**(`po_generator/integrity.py`의 `CHECKS`)를 돌린다 — 건수가 같다.
    검사 목록과 걸렸을 때 고치는 법은 [정합성검사_가이드.md](정합성검사_가이드.md)
  - 요약 표(검사 / 상태 / 건수) + 걸린 검사마다 설명과 행. `실패`는 검사 자체가 못 돈 것이다 — **0건이 아니다**
  - 맨 위 **데이터 기준**: Excel이 마지막 DB 동기화 뒤에 수정됐으면 경고가 뜬다. 그 뒤에 고친 내용은 아직 화면에 없다
    (같은 안내가 사이드바에도 한 줄 나온다 — 모든 페이지 공통)
- **마감 후 변동** — 마지막 월 마감 스냅샷이 굳은 뒤 원 데이터가 바뀌어 생긴 차이:
  - 지표 4개: **마감월 수주 변동**(마감 뒤 등록·수정·취소된 그 달 수주) / **마감월 매출 변동**(마감 뒤 그 달로 인식된 매출 —
    말일자 세금계산서를 마감 뒤에 입력한 경우 등) / **그 밖**(이전 달 주문의 변경, 환율 재평가 변화) / **잔고 변동**
  - `잔고 변동 = 수주 변동 − 매출 변동 + 그 밖`. 잔고 변동은 다음 마감 때 Variance에 **소급 변경분**으로 들어간다.
    그 달의 환율 재평가분이 같은 컬럼에 더해지므로 Variance 합계와 같지는 않다
  - 주문별 표(잔고 변동 큰 순). 납기·OS name만 바뀐 주문은 금액이 그대로라 빠지고 건수만 알려 준다.
    잔고 변동이 0인 줄(수주와 매출이 같이 들어온 주문, FX 시트에서 그 달 환율을 고친 해외 건)은 다음 마감에 아무것도
    적히지 않는다 — 스냅샷의 그 달 수주·매출만 지금 값과 다르다
  - **무엇이 바뀌었나**: 주문을 고르면 마감 시각 이후 동기화 로그에서 그 주문의 SO/DN 변경을 보여 준다
    (신규·삭제는 한 줄 요약, 수정은 바뀐 컬럼마다 한 줄)
  - 금액은 마감 엔진(`po_generator/snapshot.py`)과 같은 SQL·키·문턱으로 구한다 — 다음 달을 실제로 마감했을 때 엔진이
    적는 값과 원 단위로 같다 (`tests/test_snapshot_drift.py`)

### 동기화 로그 (2탭)

Excel → DB 동기화 때마다 무엇이 새로 생기고·바뀌고·지워졌는지의 기록이다.

- **탐색**:
  - 조회 기간, 시트·변경 유형, 주문 통합 검색, PK·컬럼명 검색 → 세션별 요약, 시트별 추이, 날짜 × 컬럼 히트맵, 상세 표, CSV
  - **보기: 전체 / 주요 변경** — 수정의 대부분은 사람이 고친 것이 아니다(30일 4,499건 중 주요 변경은 1,092건).
    `주요 변경`은 **사람이 값을 고친 수정과 삭제**만 남긴다. 빼는 것:
    - 최초 입력(빈칸 → 값)과 신규 행. **값을 지운 것(값 → 빈칸)은 남긴다** — 인식일을 지우면 매출 인식이 취소된다
    - 자동으로 바뀌는 열(수식 열, `Seq`) — 목록은 화면의 '주요 변경에서 숨기는 것'에서 볼 수 있다
    - `Status` — 진행 표시라서. 단 **취소·보류가 걸린 전환은 남긴다** (`미출고 → Cancelled`, `Hold → 미출고` 등)
    - 표기만 바뀐 것 (`2026-11-15` → `2026-11-15 00:00:00`, `1` → `1.0`)
  - **범위** (주요 변경일 때): 전부 / 판매 수량·단가 / **매입 수량·단가**(PO의 Item qty·ICO Unit) / 납기·일정 /
    출고·매출 인식 / 거래처·주문번호 / 취소·보류
  - 주요 변경의 상세 표는 바뀐 컬럼마다 한 줄이고 숫자면 **변동률(%)** 이 붙는다 — 열 머리를 눌러 큰 변동부터 볼 수 있다
    (예: 매입단가 175,576 → 441,818 = +151.6%). 삭제는 한 줄로, 무엇이었는지와 함께
  - 삭제는 **문서째 삭제**(지금 그 시트에 그 번호가 없다)와 **행 삭제**(문서는 남아 있다 — 라인 정리·재키잉)로 나뉜다.
    지금 상태로 가르는 것이라, 같은 번호로 다시 등록했으면 '행 삭제'로 보인다
- **주문 타임라인**:
  - 번호 하나로 SO ↔ PO ↔ DN 전체 이력을 시간순 카드로. **SO/PO/DN 번호 외에 고객 PO·AX Project 번호**로도 찾는다
    (전체 일치, 대소문자·앞뒤 공백 무시). 지워져서 지금 시트에 없는 주문도 번호로 찾으면 이력이 나온다
  - 카드 요약: 신규·삭제는 그 행이 무엇이었는지(고객·품목·수량·단가·금액·일자), 수정은 사람이 고친 열을 먼저.
    '전체 보기'를 펼치면 모든 컬럼이 표로 나온다

## 4. 향후 계획 — ERP 데이터 활용

현재는 NOAH 데이터만 대상이지만, 동일한 방식으로 ERP 데이터 활용이 가능합니다.

```
ERP (D365 / AX2009) → Excel/CSV 다운로드 → DB 동기화 → Dashboard
```

확장 가능 영역:

| 데이터 | 활용 |
|--------|------|
| Trial Balance (TB) | P&L, BS 월별 추이 대시보드 |
| AP/AR Aging | 미수금/미지급 현황 |
| 재고 데이터 | 재고 회전율, 과잉재고 분석 |

ERP에서 Excel/CSV로 데이터를 내려받으면, 원하는 형태의 분석 대시보드를 만들 수 있습니다.

## 5. 문제 해결

| 증상 | 해결 |
|------|------|
| 아이콘을 눌러도 반응 없음 | 설치 폴더의 `NOAH 대시보드.bat` 실행 → 검은 창의 오류 메시지를 담당자에게 전달 |
| "데이터 파일을 찾지 못했습니다" | OneDrive 동기화 완료 확인 → 안 되면 `설정.bat` 으로 폴더 경로 지정 |
| 빈 화면 (데이터 없음) | 데이터 새로고침 버튼 클릭 / `설정.bat` 의 경로 확인 |
| 포트 충돌 | 실행할 때마다 빈 포트를 자동으로 확보하므로 발생하지 않습니다 |
| 상단에 경고 배너 표시 | 일부 데이터 로더가 실패한 상태. 배너에 표시된 테이블/에러 확인 후 `python sync_db.py` 재실행 또는 DB 스키마 점검 |
| "데이터 기준"이 며칠 전 | 담당자가 아직 동기화하지 않았거나 OneDrive 동기화가 밀린 상태 |
| 설치/업데이트가 실패 | 대시보드가 켜져 있으면 파일을 못 바꿉니다. 브라우저와 서버를 닫고 다시 실행 |
