# 원산지증명서(COO) — 왜 만들었고, 언제 쓸 수 있나

> 운영자 관점 가이드. 생성은 `create_coo.py` (메뉴 `noah_menu.bat` [해외] [8] / `create_po.bat` [O] / GUI),
> 셀 매핑은 `docs/TEMPLATE_MAPPINGS.md` COO 절, 코드 규칙은 `CLAUDE.md` Business Rules COO 항목이 소유한다.

## 한 줄 요약

상공회의소 COO를 건마다 비용을 내고 받는 대신, **RCK가 직접 발행하는 원산지 선언서**를 업체가 받아 줄지
제안하려고 만든 양식이다. 업체가 받아 줘야 쓸 수 있다 — **2026-10-14 기준 제안 전**.

```
python create_coo.py DNO-2026-0001     ← xlsx + PDF (generated_coo/)
```

---

## 배경

- 해외 업체가 원산지증명서(COO)를 요청했다.
- 생산 공장인 NOAH는 **인증수출자가 아니어서** 자체 원산지증명을 해 줄 수 없다.
- 그래서 지금 줄 수 있는 건 **RCK가 대한상공회의소에서 발급받는 COO**뿐이고, 발급할 때마다 비용과 시간이 든다.
- → **RCK가 수출자로서 자체 발행한 원산지 선언서**로 대신해도 되는지 업체에 제안한다.

양식은 업체가 보내 준 다른 공급사의 자체 선언서(Bifold 'Certificate of Country of Origin')를 본보기로 했다.

## 상공회의소 COO와 무엇이 다른가

| | 상공회의소 COO (지금) | 이 양식 |
|---|---|---|
| 성격 | 상의가 인증한 원산지증명서 | **수출자(RCK)의 자체 선언** |
| 서명 | 신청자 + 상의 인증 | RCK (서명 이미지 자동) |
| 비용·시간 | 건별 수수료, 신청·발급 대기 | 없음 — 출고 건으로 바로 생성 |
| 원산지 근거 | 상의 심사 | NOAH가 RCK에 내주는 **원산지확인서** (RCK 보관) |
| FTA 관세 혜택 | 이것도 아니다 (FTA는 협정별 원산지증명서) | 불가 |

## 쓸 수 있는 조건

1. **업체(와 수입국 세관)가 자체 선언을 받아 줘야 한다.** 결정은 업체가 한다. 단순 원산지 확인·내부 관리
   용도면 받아 주기도 하지만, 수입국 규정이나 업체 방침상 상의 인증본이어야 하는 경우가 있다.
2. **FTA 관세 혜택용이 아니어야 한다.** 그건 협정별 원산지증명서(인증수출자 자율발급 또는 기관발급)가 필요하다.
3. **인증수출자 자격은 필요 없다.** 인증수출자는 FTA 원산지 자율발급의 요건이고, 이 양식은 FTA용이 아닌
   일반 원산지 선언서다. NOAH가 인증수출자가 아닌 것이 이 방식의 걸림돌이 되지 않는다.
4. **RCK가 NOAH의 원산지확인서를 갖고 있어야 한다.** RCK는 생산자가 아니라서, 선언의 근거를 생산자에게서
   받아 둔다 (건별 또는 기간 단위 포괄). 허위 선언 책임은 서명한 RCK가 진다.

### 업체에 먼저 확인할 것

- COO를 **어디에 쓰는지** — 단순 원산지 확인 / 수입 통관 서류 / FTA 관세 혜택
- **상의 인증본이어야 하는지**
- 받아 준다면 이 양식에 **더 필요한 항목**이 있는지 (아래 '보완 후보')

## 양식이 이렇게 생긴 이유

모든 결정이 위 배경 — **상의 COO를 대체하자고 제안한다** — 에서 나온다.

| 결정 | 이유 |
|---|---|
| 선언·서명은 RCK, 생산 공장 NOAH는 `Manufacturer`로 | 상의 COO도 RCK가 수출자로 신청한다 — 같은 주체가 직접 선언하는 것으로 바뀔 뿐이다. 생산 사실은 NOAH 원산지확인서로 받친다. CI·PL의 Seller와도 같다 |
| 부제 `Exporter's Declaration of Origin` | 상의 인증본으로 오인되지 않게 성격을 밝힌다. 대체를 '제안'하는 문서라 투명해야 업체가 판단하기 쉽다 |
| 상의 COO와 같은 정보를 싣는다 | 업체가 늘 받던 정보가 다 있어야 대체를 받아 준다 (아래 대응표) |
| CI와 같은 데이터·번호·HS Code | 세관이 CI와 맞춰 본다. DN 하나로 CI·PL·COO가 같이 나온다 |
| RCK 서명 이미지 자동 삽입 | 목적이 건별 비용·수고를 없애는 것 — 사람이 서명할 일이 없어야 한다 |
| 선언문은 본보기(Bifold) 문구 그대로 | 실제로 통용되는 자체 선언 문구다. 보관 기간 같은 약속을 더하지 않는다 (FTA 규칙의 '5년 보관'을 넣었다가 뺐다) |
| 운임 줄(FEDEX COST 등) 제외 | 원산지를 증명할 물건이 아니다 |

### 상의 COO 항목과의 대응

일반적인 상의 COO 서식 기준이다 — 실제 발급본과 한 번 대조해 볼 것.

| 상의 COO 항목 | 이 양식 |
|---|---|
| Exporter | Exporter (RCK) |
| Consignee | Consignee (`Customer_해외` Bill to 1~3) |
| Means of transport and route | Means of Transport (운송 방법 + 선적항 INCHEON) — **출항일·선박/편명 없음** |
| Country of destination | Country of Destination |
| Marks and numbers / Number and kind of packages | **없음** |
| Description of goods | Model No. / Description (+ Item No.·HS Code) |
| Quantity | Qty |
| Number and date of invoices | Commercial Invoice No. — **날짜는 따로 없다** (Date of Issue가 CI 날짜와 같다) |
| Country of origin | Country of Origin (REPUBLIC OF KOREA) |
| — | (추가) Manufacturer(NOAH), Order No., Customer Order No., Line |

### 보완 후보 (결정 필요)

업체가 상의 COO와 같은 수준을 원하면 더할 수 있는 것. 지금은 넣지 않았다.

- **인보이스 날짜** — `Commercial Invoice No.` 옆에 CI 날짜를 병기 (데이터 있음, 간단)
- **출항일** — `DN_해외.선적일`(없으면 `선적 예정일`). 선박명·편명은 데이터에 없다
- **포장 수·화인(Marks)** — 데이터에 없다. 필요하면 PL과 같이 입력 경로부터 정해야 한다

## 운영 순서

1. 업체에 제안 — 샘플 PDF와 함께 용도·인증본 필요 여부를 묻는다
2. 받아 주면 → NOAH에 원산지확인서를 요청해 RCK가 보관
3. 출고 건마다 `create_coo.py DNO-…` → PDF를 CI·PL과 함께 보낸다 (xlsx는 손볼 때 쓰는 원본)
4. 받아 주지 않거나 FTA 용도면 → 지금처럼 상의 COO
