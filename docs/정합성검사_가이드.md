# 데이터 정합성 검사 — 한눈에 이해하기

> 운영자 관점 가이드. 검사 산식은 `po_generator/integrity.py`(`CHECKS`), 실행기는 `check_data.py`가 소유한다.

## 한 줄 요약

**정상이라면 한 건도 없어야 하는 것**이 정말 0건인지 DB에서 확인하고, 걸린 건은 엑셀 시트에서 사람이 고친다.
이 도구는 시트를 건드리지 않는다.

```
python check_data.py        ← 또는 create_po.bat 메뉴 [V]
```

---

## 언제 돌리나

| 시점 | 왜 |
|------|----|
| **[8] DB Sync 직후** | 검사는 DB를 읽는다. 동기화 전이면 방금 고친 것이 아직 안 보인다 |
| **[N] DN 출고기록 자동 입력 뒤** | 새 DN 행의 단가 불일치·거래처 섞임·SO 참조 오기를 바로 잡는다 |
| **[9] 월 마감 전** | 마감 뒤에 고치면 그 수정이 다음 달 Order Book에 **Variance**로 잡힌다 ([PERIOD_CLOSE_GUIDE.md](PERIOD_CLOSE_GUIDE.md)) |

검사 전체가 2초 남짓이라 아무 때나 돌려도 된다.

## 결과 읽는 법

```
NOAH 데이터 정합성 검사
============================================================
DB: ...\noah_data.db
데이터 기준: 2026-10-13 10:23 (마지막 DB 동기화)
[주의] Excel이 마지막 동기화 이후 수정됐습니다 (2026-10-13 14:36).
       그 뒤에 고친 내용은 아직 DB에 없습니다 — 먼저 DB Sync를 돌리세요 (메뉴 [8] / python sync_db.py).

  [정상] SO/DN 과다출고          0건
  [정상] SO/DN 단가 불일치       0건
  ...
  [문제] 한 DN에 거래처 둘       1건
  [정상] 환율 없는 외화 DN       0건

------------------------------------------------------------
[문제] 한 DN에 거래처 둘 (1건)
  (무슨 문제이고 무엇을 고치는지 설명)

  시장  DN_ID          거래처                                       SO_ID
  국내  DND-2026-0328  주식회사 코콘 (...) / 주식회사 한일전자 (...)  SOD-2026-0379, SOD-2026-0383

============================================================
문제 1개 (검사 8개 중)
결과: ...\generated_check\정합성검사_결과.xlsx
```

| 표시 | 뜻 | 할 일 |
|------|----|------|
| `[정상]` | 0건 | 없음 |
| `[문제]` | 걸린 건이 있다 | 아래 [검사 목록](#검사-목록) 표대로 시트를 고친 뒤 [8] DB Sync → 다시 검사 |
| `[실패]` | 검사 자체가 못 돌았다 (컬럼 개명·테이블 누락 등) | **0건이 아니다** — 오류 문구를 보고 코드를 고쳐야 한다. 나머지 검사는 계속 돈다 |
| `[주의]` | Excel이 마지막 동기화보다 새롭다 | 이미 고친 문제가 계속 보이거나, 방금 생긴 문제가 안 보일 수 있다. [8] DB Sync 먼저 |

- 콘솔에는 검사당 10행까지만 보인다. 전부는 **결과 파일** `generated_check/정합성검사_결과.xlsx`에 있다 —
  `요약` 시트 + 걸린 검사마다 한 장
- 결과 파일은 **하나를 매번 덮어쓴다 — 모두 정상이어도.** 고친 뒤 다시 돌리면 그 파일이 '정상'으로 바뀐다.
  `요약` 표 아래에 **검사 시각·데이터 기준**(그리고 DB가 낡았으면 주의)이 적혀 있어, 언제 결과인지 파일만 봐도 안다
- 결과 파일을 Excel로 **열어 둔 채** 다시 돌리면 덮어쓰지 못하고 `[경고] 결과 파일이 Excel에 열려 있어…`가 뜬다 —
  열린 창은 지난 결과다. 닫고 다시 실행
- 예전(2026-10-13 오후까지)에는 문제가 있을 때만 `정합성검사_YYMMDD_HHMMSS.xlsx`를 새로 만들었다 — 그 이름의 파일은
  지난 결과이니 지워도 된다
- 종료 코드: 0 = 모두 정상, 1 = 문제가 있거나 검사를 못 함 (배치에서 관문으로 쓸 수 있다)

## 검사 목록

모두 **0건이 정상**이다. 취소·보류(`Cancelled`/`Hold`) SO 라인은 해당 검사 외에는 보지 않는다.

| 검사 | 무엇을 보나 | 걸리면 | 실제 사례 |
|------|-----------|-------|----------|
| **SO/DN 과다출고** | SO 라인별 DN 출고수량 누계 > SO 주문수량 | DN 수량 오기인지, 다른 라인 번호로 적어야 할 출고인지 확인 → `DN_국내`/`DN_해외` 수정 | — |
| **SO/DN 단가 불일치** | DN 금액 ≠ SO 단가 × DN 출고수량 (1원·0.1% 미만은 무시, 외화는 외화끼리) | DN 행의 단가·금액이 값으로 덮여 SO와 따로 놀고 있는지 먼저 본다. 맞는 쪽을 기준으로 다른 쪽을 고친다. 대시보드 '오늘의 현황 → SO/DN 불일치' 카드와 **같은 함수**라 숫자가 같다 | — |
| **SO에 없는 DN 라인** | DN의 `(SO_ID, Line item)`이 SO 시트에 없음 | DN의 SO_ID·Line item 오기를 고친다. 그대로 두면 DN 단가 XLOOKUP이 비고 Order Book에서 매출이 어느 주문에도 안 붙는다 | — |
| **취소·보류 SO 라인의 DN** | SO Status가 `Cancelled`/`Hold`인 라인에 출고 기록 | 실제로 나갔으면 SO Status를, 아니면 DN 행을 고친다. **보류 전에 일부 나간 라인**이면 그대로 둬도 된다 | — |
| **PO에 없는 SO** | 살아 있는 SO인데 PO 시트에 그 SO_ID가 **한 줄도** 없음 (주문 단위) | PO를 등록하거나, 주문이 취소됐으면 SO Status를 `Cancelled`로. 출고 완료 주문도 센다 — 나간 주문에 PO가 없으면 매입이 기록되지 않은 것이다 | — |
| **SO에 없는 PO** | PO에 적힌 SO_ID가 SO 시트에 없음 (공란 포함, 취소된 PO도 셈) | SO를 지웠다면 되살려 Status를 `Cancelled`로 (지우면 취소 기록까지 사라진다), 아니면 PO의 SO_ID 오기를 고친다 | — |
| **한 DN에 거래처 둘** | 한 DN_ID에 거래처가 둘 이상 (DN 번호 재사용) | 시트에서 DN_ID를 나눈다. 그 문서는 거래명세표 메일에서도 자동으로 빠진다 — 남의 품목·단가가 찍히기 때문이다 | `DND-2026-0328` 코콘 + 한일전자 |
| **환율 없는 외화 DN** | 선적한 해외 DN인데 그 달 환율이 FX 시트에 없음 | FX 시트에 그 달 환율을 넣고 [8] DB Sync. 그 전까지 Order Book 매출은 **오류 없이** 수주시점 환율(`Total Sales KRW`)로 잡힌다 | — |

### 판정에서 알아 둘 것

- **'PO에 없는 SO'는 라인이 아니라 주문 단위다.** PO는 부속·운임을 한 라인에 합쳐 적는다(`SA09X-MA + ADAPTER`,
  `FEDEX COST` 등). 라인 번호로 맞추면 같은 번호의 PO가 없는 SO 라인이 32개 나오는데(2026-10) 거의 전부
  운임·합산 부속·할인·보증이다. SO와 PO는 99.2%가 같은 동기화에 들어오므로 유예 기간은 없다 — 걸리면 PO 입력이 밀린 것이다
- **'한 DN에 거래처 둘'의 거래처 키**는 그 시장의 문서가 쓰는 열이다. 국내는 `DN_국내.Business registration number`
  (하이픈 무시), 해외는 `SO_해외`의 고객코드. 빈 사업자번호는 '다른 거래처'로 세지 않는다
- 대시보드 '발주 커버리지'의 **PO 미등록**과 'PO에 없는 SO'는 같은 정의지만 대시보드는 출고 완료 주문을 뺀다.
  그래서 숫자가 다를 수 있다 (여기가 더 많거나 같다)

## 동기화가 "키가 같은 행"으로 멈출 때

정합성 검사가 아니라 **[8] DB Sync**가 내는 에러다. 같이 알아 두면 좋다.

```
[에러] PMT_국내:
  - 키(선수금_ID)가 같은 행이 1건 있습니다 — 뒤 행이 앞 행을 덮어써 한 줄이 DB에서 사라지므로
    동기화하지 않았습니다. 엑셀에서 키를 고친 뒤 다시 실행하세요.
  - ADV_2026-0062 — 엑셀 2, 3행
```

- **왜 막나**: `SO_국내`·`SO_해외`는 `(SO_ID, Line item)`, `PMT_국내`는 `선수금_ID`가 곧 DB의 키다. 같은 키가 두 줄이면
  뒤 줄이 앞 줄을 **덮어써** 한 줄이 DB에서 조용히 사라진다. 실제로 `ADV_2026-0062`가 동기화 41회 동안 서로 다른 두 입금
  (정광산업기계 396,000원 / 엠피티 6,600,000원)에 쓰여 한쪽이 대시보드에 없었다 (2026-09-22 해소)
- **고치는 법**: 에러에 나온 **엑셀 행 번호**로 가서 키를 고친다 — SO는 Line item 번호, 선수금은 선수금_ID. 그리고 [8] 다시
- **막히는 범위**: 동기화 전체가 되돌려진다 — 다른 시트의 변경도 이번엔 안 들어간다. DB는 직전 상태 그대로다
- `1`과 `1.0`은 같은 라인으로 본다. 키가 빈 행은 막지 않고 원래대로 '미완성 행'으로 보류한다
- PO·DN 시트는 분할 행을 위해 `_row_seq`를 붙이므로 이 에러가 나지 않는다
- 이 사고는 DB에 이미 덮인 뒤라 `check_data.py`로는 잡을 수 없다 — 동기화 시점에만 보인다

## 일부러 보지 않는 것

**늘 몇 건씩 있는 게 정상인 것은 넣지 않는다.** 섞으면 결과가 항상 빨갛고, 결국 아무도 안 본다.
처리할 일 목록(세금계산서 미발행·PO 확정 지연·EXW 미출고·납기 지연)은 대시보드에 있다.

실데이터에서 재 보고 뺀 후보 (2026-10-13):

| 후보 | 걸린 건 | 뺀 이유 |
|------|--------|--------|
| DN 단가 0원 | 12행 | 전부 SO 단가도 0원 — 무상 라인 |
| 세금계산서 발행일 < 출고일 | 31 DN | 차이 1~22일, 여러 거래처에 고르게 — 선발행 관행으로 보임 |
| DN과 SO의 Customer PO 다름 | 20행 | 브이티엘이 라인마다 PO 번호(-01~-12)를 따로 쓰는 구조 |
| PO 완전 동일 행 | 3쌍 | 전부 균등 분할(1+1, 212+212, 20+20)이고 SO·DN 수량과 맞음 |
| PO 공장단가 0 | 36행 | 대부분 Open·Holding — 단가 미정 발주(작업 목록) |
| 출고일 < 주문 접수일 | 5행 | 절반은 접수일 오타가 원인, 나머지는 선출고일 수 있음 |
| SO 금액 ≠ 수량 × 단가 | 1행 | 0.01 반올림 |
| DN 수량 ≤ 0 | 1행 | 반품 (`SOD-2026-0280`) |

재 봤고 쓸 만하지만 **이번엔 보류**한 것 — 필요해지면 추가한다:

| 후보 | 지금 | 메모 |
|------|-----|-----|
| 공장 계산서는 있는데 DN 없음 | 0건 | PO가 `Invoiced Pxx`인데 그 SO의 DN이 앞뒤 한 달 안에 없음. 같은 달로만 보면 6건(1월 말 출고 → 2월 계산서)이라 ±1달이 필요하다 |
| SO 접수일 오타 | 7주문 | 접수일이 Period보다 늦거나 3개월 넘게 이름. 2028·2029·2022·1900년 같은 오타가 실제로 있다 — 납기현황 메일이 접수일 순 정렬이라 표 맨 위·맨 아래로 튄다 |

## 검사를 추가하는 법

1. **실데이터에서 몇 건 걸리는지 먼저 잰다.** 걸린 것을 하나씩 열어 진짜 오류인지 본다 — 전부 정상이면 검사가 아니라 잡음이다
2. `po_generator/integrity.py`에 `conn → 문제 행 DataFrame` 함수를 쓰고 `CHECKS`에 한 줄 (`key`, 제목, 걸리면 무엇을 고치나, 함수)
3. `tests/test_integrity.py`에 걸려야 하는 경우와 **안 걸려야 하는 정상 업무**(부분 출고, 합산 부속 등)를 넣는다
4. **이 문서의 [검사 목록](#검사-목록) 표에 한 줄** — 빠뜨리면 `tests/test_integrity.py`가 실패한다

열 이름은 한글로 둔다 (콘솔과 결과 파일에 그대로 나간다). 대시보드가 같은 내용을 보여 준다면 대시보드도 그 함수를 부르게 한다 —
산식을 두 곳에 두면 한쪽만 고쳐진다.
