# 파일 분리 대비 메모 (연도 이월 전략)

> 작성일: 2026-06-04 | 상태: **대기** (현재는 단일 파일 유지)

`NOAH_SO_PO_DN.xlsx`가 OneDrive 공동 편집에 버거울 만큼 커졌을 때 어떻게 분리할지 미리 적어둔 메모.
**지금 당장 할 일은 없음.** 아래 트리거가 오면 이 방식으로 한다.

---

## 결론 한 줄

무거워지면 **연도를 통째로 자르지 말고, 미결(백로그)만 새 파일로 이월**한다.
db sync는 **옛 데이터를 모두 살리는 방향**으로 수정한다. (회계 연말 마감의 *이월*과 동일)

---

## 언제 (트리거)

다음 신호가 보이기 전엔 단일 파일 그대로 둔다:

- `파일명-PC이름.xlsx` 같은 **충돌 사본**이 생기기 시작
- 저장이 **10초 이상** 걸림
- 파일이 **수십 MB(30MB+)** 도달

→ 현재 속도 기준 **약 2년간은 불필요.** (이 시스템 자체가 ~2년 후 ERP 통합으로 대체 예정)

**현재 기준값 (2026-06-04):** 마스터 4 MB · 데이터 ~5,690행(7시트) · 전부 2026 · 증가 ~13,600행/년

---

## 어떻게 (이월 방식)

1. **미결(백로그) = 마감 시점 Ending 수량 > 0인 라인** → 새 파일로 이월
   - 이건 곧 해당 월 `ob_snapshot`(마감 잔고) 그 자체. 새로 계산할 필요 없음.
   - 주문 단위가 아니라 **라인 잔량 단위**. 부분출고 라인은 잔량만큼만 백로그.
2. **완결분(Ending = 0)** → 옛 파일에 남김 (또는 cold 보관)
3. ❌ **연도 통째 절단 금지** — SO는 작년·출고는 올해처럼 걸친 건이 끊겨 잔고가 음수/UNKNOWN이 됨.

---

## db sync 수정 방향 ("모두 살리는 방향")

현재 sync는 **mirror + prune** — 엑셀에 없는 행을 DB에서 지움 (`db_sync.py` prune 단계).
→ 파일만 쪼개면 옛 파일 데이터가 DB에서 삭제됨. 그래서 **prune을 파일/연도 단위로 한정**해야 함.

- **(A) 둘 다 sync + 파티션 prune** — 각 파일이 자기 연도 행만 prune. DB에 전 이력(라인 디테일) 유지.
- **(B) 옛 파일은 sync 제외 + 스냅샷만** — 옛 연도는 cold(비동기화), `ob_snapshot`이 집계 이력 보존. Excel·DB 둘 다 경량. 단 완결 연도의 라인 디테일은 cold 파일을 열어야 조회 가능.

→ 어느 쪽이든 라이브 Order Book/대사는 DB를 읽으므로 이월·이력 안 깨짐.

---

## 왜 단일 파일이 기본인가 (지금 안 쪼개는 이유)

- 이력이 한 곳에 남고, sync·대사·이월이 파일 경계 없이 자동으로 이어짐
- 자동화 스크립트는 마스터에 **읽기만** 함 → 공동 편집과 충돌 없음 (이 원칙은 유지할 것)
- 2년 시한 시스템에 파일 분리는 과설계

---

## 실제로 분리하는 날, 결정할 것 하나

- 완결 연도의 **라인 단위 디테일이 계속 필요**한가? → **(A)**
- **마감 잔고(집계)면 충분**한가? → **(B)** (더 가벼움)
